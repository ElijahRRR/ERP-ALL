## Q1【阻塞增量6】验收判据「同一商品三档各跑一遍」在物理上跑不通

**事实**（考古 gap [5]，本轮复核仍成立）：商品状态单向前进
（`ingested → audit_passed → listing draft → live`），跑完 auto 档就回不到 manual 档。
全仓无状态回退工具——`tools/audit_replay.py:166` 是离线重放，不改 `product.status`。
**这条会在验收当天卡住**，不是实现难度问题，是判据本身在当前状态机下无法执行。

两条路：

### (a) 三件同族商品各跑一档 ← **云端侧建议**

同一 SKU 家族取 A/B/C 三件，分别在 manual / semi / auto 下跑全链。

- 判据的**真实目的**是「三档在同一条流水线上都走得通」，三件等价输入同样证明这件事；
- **不往代码库里加任何状态回退能力**——这是关键。

### (b) 写一个 `is_test` 店专用的状态重置脚本

保住「同一商品」的字面表述，代价是往仓里引入一个**能把商品状态往回拨、且仅靠一个
`is_test` 标志把关**的通道。它会长期存在，而用到它的只有验收那一次——**收益一次性，
风险长期**。真要走这条，须配「非 `is_test` 店调用即抛」的判据并证伪过，
并考虑验收后随单删除。

**请裁定 (a) 或 (b)。** 若选 (a)，验收判据文字需由审计侧改为「三件同族商品各跑一档」
并注明理由；**裁定前云端侧照旧按原判据准备，不擅自放宽**。

## Q3【fail-open，建议增量2 一并收口】`enabled=false` 是静默安全退化

**事实**：两处读点的 SQL 都带 `AND enabled`，即**停用一行策略 = 该 flow 无行 = manual**。

在多数 flow 上这没问题（停用 → 退回人工，安全方向）。但在 `order_block` 上不是：
该 flow 的 `auto` 才是「拦截 flagged 单」，`manual` 是「只软标记不冻结」。所以
**误停用 `order_block` 策略行 = 订单拦截静默失效，且没有任何告警**。

**云端侧建议**（属实现范畴，若 Owner 无异议即照此落地，不必单独回复）：

1. 面板**显性区分三态**——「未配置 / 已停用 / manual」，不要都渲染成「人工」；
2. 读点在命中「有行但 `enabled=false`」时记一条 warn 日志（区别于「本来就没配」）；
3. `order_block` / `compliance_block` 这两条**闸类** flow 停用时，面板给显式二次确认。

不做 3 也可以，但 1 和 2 建议必做——**「看起来配着、实际没生效」是最难发现的一类故障**，
本会话已在别处栽过同形的坑（compose 从未注入 `ERP_ENV`，导致一层保护从未生效而判据全绿）。
